206 条冻结留出集，草稿 = 真人 plan（润色器的输入没有变，只是前后加了审查）。
基线 = run8 greedy 直接输出。

**语义：≤2 分从 17 条降到 7 条；风格与基线打平（0.427 vs 0.447，CI 重叠）。**

## 关键发现：A 层的两条检查是误报源

第一次跑用的是「宽 A」（标签/数字/否定/占位符/段落落地），退化 36 条，win 掉到 0.386。
把这 36 条的失败原因摊开：

| 原因 | 条数 | 判定 |
|---|---|---|
| 否定词变少 | 17 | **误报**。plan 写「是不是还有些不好意思?」，她说「有点害羞?」——反问里的「不」本来就不该照搬 |
| 占位符丢失 | 12 | **误报**。plan 有 `[player]`，她说「你」——这是正常称呼变体，不是丢信息 |
| B 判近义/方向/增减/否定 | 5 | 真问题 |

也就是说 **29/36 的退化是闸门自己制造的**。把 A 收紧到只剩「标签序列 + 数字」
（在基线输出上触发率只有 2/206 = 1.0%），退化降到 8 条，语义一分没掉，
win 从 0.386 回到 0.427。

> 教训：机械闸门的每一条检查都要单独量误报率。**宁可漏，不可错拦**——
> 错拦的代价是整条回复退化成没有风格的字面拼接，比原来那个小毛病严重得多。

## 成本

* **本地**：1.25× 生成（多出来的都是重采）
* **云端**：B 的 prompt 很短（plan + 台词 ≈ 200 token），对比编剧那一次（约 1.5k token）
  只多约 15%。但触发率高（65%），所以更适合把「含否定」这个条件去掉（→45%），
  或者干脆只在**多段**时送审。

## 建议的落地配置

```
C 机械（免费，必开）          回指 / canon 冲突 / 复读 / 能力越界
A 严格（免费，必开）          标签序列 + 数字 + 施受方向
B 触发式（多段 or 含数字）    → 目标触发率 ~45%
退化策略：重采仍不过 → 直译（3~4% 的平淡回复）
```

## 变更（2026-10-23 下午，用户否决了两处设计）

1. **不再「回编剧重写 plan」**。原链路在润色失败后会把失败原因回灌给编剧让它改，
   这违反了分工：编剧的职责是「决定说什么」，一旦让它看到下游的失败再改，
   它会开始迎合润色器的口味，而且每轮多一次不可控的云调用。
   **要约束编剧就在它输出之前约束**——现在靠 `check_plan_mechanical` 在 plan
   交付给润色器之前拦（回指 / canon 冲突 / 复读 / 能力越界 / 长度 / 第三人称）。
2. **不再「编剧直出」**。最终那句台词只能由润色器写。理由同上，另外
   `tools/compare_direct.py` 实测：同一条指令、同一份 system，润色器在盲评里
   胜 15/20（判官是 deepseek，且偏向它自己那一臂）。编剧直出的文本基本等于
   把 plan 原样搬出来加标签，没有风格增量。
