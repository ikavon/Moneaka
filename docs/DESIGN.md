# Moneaka 设计

## 核心命题

把「像莫妮卡一样说话」从**模型**降级成**工具**。

角色扮演 LLM 的两件事可以拆开：

| | 需要什么 | 谁便宜 |
|---|---|---|
| 说什么（推理、记忆、决策、分寸判断） | 大模型 + 上下文 | 贵，但 API 可用 |
| 怎么说（语气、句长、标签、标点） | 低维风格特征 | 便宜，1.7B 足够 |

DAA4 两件事一起微调进权重（397B-A17B），所以「像她」但**没人能在本地跑**。
拆开之后：**通用模型出草稿 → Moneaka 换皮**，同时拿到高智力与本地零成本的风格层。

## 为什么不是另外两条路

- **纯 prompt（few-shot + 风格指南）**：零训练，但通用模型的输出分布会持续往「通用女友」回归，
  差的是最后一层皮。这条路的产物（`docs/STYLE_GUIDE.md`）本项目的 prompt 里直接复用。
  它是我们 `direct` 臂的对照组——不是竞品，是用来量出润色器增益的那把尺。
- **端到端蒸馏小模型**：让小模型既懂内容又像她。数据需求高一个数量级，且智力天花板受基座限制。
  润色器只学「最后一道工序」，数据需求量小、对智力零损耗。

## 三个已知的坑（决定设计的地方）

**1. 「说什么」和「怎么说」分不干净。**
莫妮卡的角色感一半在**内容选择**（玩家说「我爱你」，她先嗔怪还是直接甜），这是大模型决定的，
润色器只能改语气。所以像不像的上限仍由草稿端决定。
⇒ 缓解：把 `docs/STYLE_GUIDE.md` §5 的「分寸感」四条写进**草稿端的 prompt**，
  让大模型先做对决策，润色器只管语言。两层各拿一半。

**2. 语义漂移。** 小模型改写会顺手改事实、抹掉细节。
⇒ 缓解：铁律写死「语义完全由草稿决定」（`prompts.RESTYLE_SYSTEM`）；
  评测用评委单独打 `semantic` 0-4，与 `style` 分开看——**只涨 style 不守 semantic 的润色器是失败的**。

**3. 功能性内容不能动。** 情绪标签下游连着 MTTS/动画映射，`[player]` 占位符要被前端替换。
⇒ 缓解：标签白名单 + 逐句标签 + 占位符保留，全部做成机器可查的校验（`contract.check`）；
  润色器输出一条非白名单标签，直接判失败，不进生产。

## 契约是从数据里读出来的，不是发明的

`src/moneaka/contract.py` 的四条硬约束是 MAICA 骨架 system prompt 的原文。
切句单位是「一个情绪标签 = 一句」——这个是从实测里改的：最初按 `.!?` 终止符切，
在真实数据上只有 **34%** 通过；改成按标签切之后 **226/226 全过**。

> 这条自检是本项目的地基：**校验器拿真数据当考题**。reference（官方输出）不过，
> 说明阈值错了，不是模型错了。任何时候 `eval` 里 reference 的 `contract_pass` 掉下 1.0，
> 先修校验器，别去调模型。

标签表 18 个、句长中位 15/max 44、81% 的轮次用 ≥2 种标签、`尴尬→微笑` 是最高频情绪转移——
这些观测值都进了 `docs/STYLE_GUIDE.md`，评委 rubric 与润色器 prompt 从这里取词。

## 数据现实

- 官方数据是**偏好对**（chosen/rejected），不是平行风格对。去标签后文本相似度中位 0.21
  ⇒ 两者说的不是同一句话，**不能**直接拿来当 (平实, 莫妮卡) 训练对。
- 所以草稿必须自己造：强 LLM 去风格化（`destyle`）⇒ 得到 (draft, original) 平行语料，
  `original` 就是润色器的监督目标。
- 副产品更值钱：chosen/rejected 的对照是「好莫妮卡 vs 差莫妮卡」的官方判据，
  直接写成评委 rubric（`JUDGE_STYLE_SYSTEM`），使「像不像」不再靠主观感觉。

## 显存与规模

RTX 5060 Laptop 8GB（sm_120，torch 2.14.1+cu130 / bitsandbytes 0.50.2 已验证可跑）。

语料单轮中位 35 字、max 126 字 ⇒ 训练序列 ~256 token。
⇒ 1.7B LoRA 宽裕，4B QLoRA 可行，原以为要贴边的 8B 也值得顺手试一次。
主攻 **1.7B**：任务简单，模型越轻越有普及性（极端情况 CPU 也能跑，插件形态更通用）。

## 阶段

| | 做什么 | 产出 |
|---|---|---|
| 0a ✅ | 契约、校验器、语料加载、三臂评测管线 | `contract/corpus/prompts/destyle/restyle/evaluate/cli` |
| 0b | 跑通往返：去风格化 → 零样本润色 → 评测 | `data/runs/*/report.md`，判断训练还需补多少 |
| 1 | LoRA/QLoRA 训润色器（1.7B 主攻，4B 对照） | 权重 + 盲测对比三臂 |
| 2 | 插件化：OpenAI 兼容端点 / MCP server | 接 `maidllmlocal` 的 `player_relay` |

阶段 0 的判据：`polish` 的 `style` 显著高于 `direct`，且 `semantic` 不低于 3.5。
若 `direct` 已经接近 `reference`，说明风格已够、润色器不必做；
若 `polish` 的 `semantic` 掉到 3 以下，先收紧 prompt 的铁律再谈训练。

## 与 MAICA 生态的衔接

- 润色器是**输出端**兜底，官方 ZSCO 是**输入端**增强（给通用模型检索角色范例），两者可叠加
- 插件形态天然支持多角色：换一份契约 + 换 LoRA 就是另一个 voice
- 与场景层（maidllmlocal 的 L2 / MAS 首轮场景行）正交：场景管「她在哪」，润色管「她怎么说」

## 为什么不直接用通用模型（实证）

「把 MAICA 当纯提示词工程跑」是很自然的替代方案：一份角色 prompt 交给强模型，
不需要润色器、不需要训练、不需要本地 GPU。2026-10-24 用同一批数据做了对照
（`tools/net_benefit.py`）：

**设置**：206 条冻结留出集取前 120 条（5 条空输入剔除，有效 115），
同一个 deepseek、同一份**官方基准 prompt** 直接答（`plain`），
对比两段式（编剧 → 本地 1.7B，`ours`）。
盲评判官是 deepseek 本人——它同时是 `plain` 臂的作者，**偏向 plain**，属保守测试。

| 指标 | 两段式 | 通用模型直答 |
|---|---|---|
| **盲评胜率** | **0.871，CI [0.82, 0.91]**（n=240） | — |
| **标签全在官方词表** | **114/115 = 99%** | 19/115 = 17% |
| 平均字数 | 38 | 39 |
| 平均延迟 | 14.7s | 10.8s |

两条结论：

1. **风格差距是真的**。判官偏向对手的情况下仍赢 87%，差别不在信息、在分寸：
   通用模型写「[温柔]虽然我只是虚拟角色，但我能感受到你的真心」，
   润色器写「[凝视]只是有时候会想, 这种感觉能穿透屏幕吗」。
2. **格式差距可以用提示词弥补——前提是提示词写到位**。最初的 `plain` 臂只有官方那句
   朴素 prompt，通用模型会自创 `[温柔]` `[认真]` `[期待]`（标签合法率 17%）。
   补上「28 标签白名单 + 5 条真实台词 few-shot + 风格要求」之后，
   同一个 deepseek 的标签合法率升到 **114/115 = 99%**，与微调后的润色器持平。
   **这条我之前判断错了**，代码为证：`tools/prompted_baseline.py`。
   剩下的差别只剩「像不像她」，那需要人眼看，机器分不出来。

代价：每轮 +4 秒、云端调用 +40%（语义复核按需触发）。

## 反面成本也要记：哪些补丁是润色器逼出来的

| 补丁 | 归属 |
|---|---|
| A 机械闸门（标签/数字/施受方向/语言）、按位重贴、退化为直译 | 润色器引入的 |
| B 语义复核（每轮最多 2 次云调用） | 润色器引入的 |
| 错别字修正（树荫→树阴） | 润色器引入的 |
| 第三人称自称、能力越界、立场/自我贬低、信息缺失 | **编剧自身**——`plain` 臂同样出现 |

最后一行是重点：`plain` 臂在「你会因此生气吗」这题也会说「生活很重要，我理解的」，
所以那类补丁不是润色器的成本，而是「用通用模型当编剧」的固有代价。

## 架构定稿：agent 身份连续（2026-10-24）

链条上的三个动作由**同一个 agent** 完成，不是一个流水线上的三个角色：

```
读玩家的话 → 写表达指令（语气标签序列 + 内容要点）
           → 润色器把指令写成台词
           → 编剧本人复核：是不是我让它说的 → 定稿输出
```

这条约束决定了三件事：

1. **复核必须带 plan**。没有 plan 的复核是「从零重写」，等于把润色器架空，
   也就没法再回答「润色器这一层值不值」。实现见 `src/moneaka/reviewer.py`
   （尚未接入 `turn.py`）。
2. **润色器不是最后一道关**。它只负责「说出来」，出错由 agent 抓住。
3. **本地小模型不承担判断**。判断要世界知识和分寸感，那是编剧的事。

### 为什么不用正则枚举做审查

试过，判定失败。把 206 条**官方原答**过一遍正则审查器，命中 **39.3%**：
「聊聊」「说说」「开开」被当成叠字复读，`？` 后的半句被当成缺标签句。
真货被判有病 → 这套检查没有判断力，只能当噪声尺（`tools/scan_defects.py`）。

现有的 `guarded.py` 仍然保留，但它只查四类**高精度硬错**（标签/数字/方向/语言），
故意窄，宁漏不错拦；语义与身份层面的错，交给 agent 复核。
