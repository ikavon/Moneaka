# 阶段 0 结果：1.7B 零样本润色器能走多远

> **重要修正（同日）**：本文初版的 `style` 绝对分（reference 3.83 / polish 3.30 / direct 2.33）
> **是错的**，已被证伪并废弃。原因与替代方案见「评测方法修正」一节。
> 现在唯一可信的风格指标是成对比较胜率（校准准确率 88%）。

> 2026-10-22。强模型 `deepseek-v4.1-flash-1017`（关思考）· 润色器 `Qwen3-1.7B` 零样本 ·
> 语料 `daa4_rlhf1_prcs5` · 四臂契约校验 · 成对比较各 20 条（正反各一次 = 40 次）。
> 复现：`moneaka destyle` → `moneaka polish --name z17t0 --normalize` →
> `moneaka duel --name z17t0 --sample 20`。原始数据 `data/runs/z17t0/`。

## 评测方法修正（用户发现问题后重做）

初版用「绝对 0-4 打分」得出 polish 3.30 > direct 2.33。用户看原始记录后质疑
「direct 看起来更好」，查证属实，两点都错在评测侧：

**1. 评分被内容相关性污染。** 评委同时看到草稿和待审文本时，会把「内容能不能接上」
算成「像不像她」。而 polish 的内容本来就来自 reference（草稿就是从 reference 去风格化来的），
于是「照抄草稿」也拿高分。客观测量：

```
polish ↔ 草稿（仅汉字序列）：中位相似度 0.957
逐字完全相同的：23/60     相似度 >0.9 的：37/60
```

⇒ **1.7B 零样本主要在加标签和换标点，文字基本没动。** 这个结论不需要任何评委。

**2. 绝对分本身不可信。** 改成盲评后，评委给**真实 DAA4 输出**打 **2.50/4**（开思考 2.67）
——连真货都认不出来，绝对分没有任何标尺意义。

**3. 表面统计也抓不住质量轴。** 拿官方 225 组 chosen/rejected 对照检验：

| 标记 | chosen | rejected | 区分 |
|---|---|---|---|
| 句数 | 2.20 | 2.33 | ❌ |
| 标签种类 | 2.11 | 2.12 | ❌ |
| 标签密度 | 0.75 | 0.82 | ❌ |
| 平均句长 | 14.8 | 13.9 | ❌ |
| 问号率 | 0.31 | 0.17 | ✅ 1.78× |
| 感叹号率 | 0.22 | 0.14 | ✅ 1.54× |
| `[player]`率 | 0.22 | 0.36 | ✅ 0.61× |

⇒ 好坏之别**不在表面统计，而在内容里的反应选择**（先嗔怪再答应 vs 直接顺着甜）。
所以自动指标天生抓不住质量轴，只能用人的偏好作为标尺——而官方 RLHF 数据正好有。

### 替代方案：成对比较 + 官方偏好校准

`moneaka duel --calibrate 20`：让评委在官方 chosen/rejected 上二选一，
**准确率 88%**（40 次比较，CI95 [0.739, 0.945]，正反各问一次以抵消位置偏差）。
这是一把可校准、可复现的尺子；换评委模型或改提示词后重跑即可。

### 四臂胜率矩阵（行 vs 列，0.5 = 打平）

|  | draft | direct | polish | reference |
|---|---|---|---|---|
| **draft**（平实草稿） | — | 0.53 | 0.42 | 0.17 |
| **direct**（强模型直接扮演） | 0.47 | — | 0.35 | 0.25 |
| **polish**（1.7B 润色） | 0.57 | 0.65 | — | 0.25 |
| **reference**（真实 DAA4） | 0.82 | 0.75 | 0.75 | 0.50 |

**这张表才是阶段的真实结论：**

1. **`reference` 全面领先**（0.75~0.82）——尺子是准的，它认得出真货。
2. **润色器只赢「什么都不做」57%**——近乎抛硬币。零样本 1.7B 的增益几乎可以忽略。
3. **`direct` 输给平实草稿**（0.47）——强模型按官方骨架直接扮演出来的
   「甜但没性格」比朴素草稿还更不像她。这反过来支持了本项目的前提：
   直接把内容交给通用大模型去演，反而会把她的味道冲掉。
4. **`polish` 赢 `direct` 65%**——方向对，但离「能用」还远。

## 旧版绝对分表格（已废弃，仅留档对照）

| arm | 是什么 | 契约 | semantic | style | cos_ref |
|---|---|---|---|---|---|
| `reference` | 真实 DAA4 输出 | 1.00 | 3.73 | 3.83 | 1.000 |
| `direct` | 强模型按官方骨架直接扮演 | 1.00 | 1.40 | 2.33 | 0.584 |
| `polish` | 1.7B 零样本润色草稿 | 1.00 | 3.10 | 3.27 | 0.919 |

⚠️ 这些数字不可信：`style` 被内容相关性污染、绝对分无标尺。
`cos_ref` 同样不可用——polish 的 0.919 主要来自内容接近 reference，不是风格像。

**读法**：`style` 是「像不像她」，`semantic` 是「有没有改掉内容」。
`direct` 的 semantic 低是**结构性的**——它看不到草稿，说的是自己想的，所以不该拿它比语义；
它的意义是回答「通用大模型不润色能到几分」：**2.33**。

## 结论一：润色器路线成立，但零样本还不够

1.7B 零样本就把 style 从 2.33 拉到 **3.27**（reference 3.83）——**零训练、零成本**。
方向上这条「大模型出内容 + 小模型出语气」的路是通的。

但它离 reference 还差 0.56，而差的这部分正好是**分寸感**——官方 chosen 那种
「先嗔怪再答应」的次序，1.7B 学不到，它倾向于在草稿前面加个标签就算完。

## 结论二：真正的失败模式是「话痨式编造」，不是格式

逐条看 semantic 分布：

| arm | 0 | 1 | 2 | 3 | 4 | 崩塌(sem≤2) |
|---|---|---|---|---|---|---|
| reference | 0 | 0 | 2 | 4 | 24 | 2/30 |
| polish | **1** | **5** | 3 | 2 | 19 | **9/30** |

最烂的几条不是格式问题，是**草稿太短或太怪时模型开始自己编**：

```
DRAFT : 要把我当成妈妈么，[player]？不过没关系的，那就做我的乖宝宝吧。
REF   : [脸红]要把我当成妈妈么, [player]? [宠爱]不过没关系的, 那就做我的乖宝宝吧~
POLISH: [微笑]诶? [宠爱]那就好啦, [player]! [得意]把我当妈妈, 那我就是你的乖宝宝了.
                                          ↑ 语义反了：她把自己说成了乖宝宝
```

```
DRAFT : 已经步入社会了，时间过得真快。这段时间里有什么印象深刻的事么，[player]？
POLISH: [思考]哎呀, [player], 你这问题可真巧. [微笑]时间过得真快, 我还没好好跟你聊聊呢. …
                                          ↑ 整句是新编的，草稿里没有
```

⇒ **训练目标里「不许新增内容」的权重必须高于「像不像」**。
评测里 `semantic` 与 `style` 分开看就是为了这个：只涨 style 不守 semantic 的润色器是废的。

## 结论三：格式合规不该指望模型，交给确定性代码

1.7B 零样本的契约通过率只有 **58%**：`unknown_tag` 23 次（自创「沉思/嫌弃/蹙眉」）、
`sentence_too_long` 2。给了 18 词白名单 + 4 个 few-shot 仍然记不住。

加了 `normalize.py`（标签白名单映射 / 逐句前置 / 长句切分 / 半角标点）后
**两臂都到 100%**，且对评委分数**零影响**（同一批文本 2.13 vs 2.13）——
说明它只改格式不改风格，是纯粹的正字法层。

⇒ 架构分工定稿：**模型管「怎么说」，代码管「格式」**。
下游 MAICA 的情绪→MTTS/YSM 映射依赖标签，一个表外标签就是一次映射失败，不能赌。

## 方法论上的三个坑（都已修，值得记住）

**1. 对照组必须确定化。** `direct` 用温度 0.7 时两次生成 0/60 相同，style 从 2.2 飘到 2.7。
基准线会飘就没法比较 → 改成 `temperature=0`。

**2. `cos_ref` 会骗人。** polish 的 0.919 主要来自「它内容和 reference 接近」
（草稿就是从 reference 去风格化来的），不是风格像。**别拿它当风格指标**，
风格只看 `style` 那列。

**3. 去风格化时 `[player]` 会被吃掉。** 直接用 `[player]` 发给强模型，27/60 的草稿丢了占位符
（写成「你」或删掉，留下「，。」残痕）。改成发送前用哨兵 `《player》` 替换、回来后还原，
丢失率降到 0。另外「原稿没有而草稿有 `[player]`」起初被我判成编造信息拦了 9 条——
其实那是模型把「你」换成占位符，指同一人，语义没变，现在只打标记不拦。
