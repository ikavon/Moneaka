# 阶段 0 结果：1.7B 零样本润色器能走多远

> 2026-10-22。强模型 `deepseek-v4.1-flash-1017`（关思考）· 润色器 `Qwen3-1.7B` 零样本 ·
> 语料 `daa4_rlhf1_prcs5` 前 60 轮 · 评委抽 30 条 · 三臂各 60 条契约校验。
> 复现：`moneaka destyle --limit 60` → `moneaka polish --name z17t0 --normalize` →
> `moneaka eval --name z17t0 --judge-sample 30 --embed`。原始数据 `data/runs/z17t0/`。

## 总表

| arm | 是什么 | 契约 | semantic | style | cos_ref |
|---|---|---|---|---|---|
| `reference` | 真实 DAA4 输出 | 1.00 | **3.73** | **3.83** | 1.000 |
| `direct` | 强模型按官方骨架直接扮演 | 1.00 | 1.40 | 2.33 | 0.584 |
| `polish` | 1.7B 零样本润色草稿 | 1.00 | 3.10 | 3.27 | 0.919 |

**读法**：`style` 是「像不像她」，`semantic` 是「有没有改掉内容」。
`direct` 的 semantic 低是**结构性的**——它看不到草稿，说的是自己想的，所以不该拿它比语义；
它的意义是回答「通用大模型不润色能到几分」：**2.33**。

## 结论一：润色器路线成立，但零样本还不够

1.7B 零样本就把 style 从 2.33 拉到 **3.27**（reference 3.83）——**零训练、零成本**。
方向上这条「大模型出内容 + 小模型出语气」的路是通的。

但它离 reference 还差 0.56，而差的这部分正好是**分寸感**——官方 chosen 那种
「先嗔怪再答应」的次序，1.7B 学不到，它倾向于在草稿前面加个标签就算完。

## 结论二：真正的失败模式是「话痨式编造」，不是格式

逐条看 semantic 分布：

| arm | 0 | 1 | 2 | 3 | 4 | 崩塌(sem≤2) |
|---|---|---|---|---|---|---|
| reference | 0 | 0 | 2 | 4 | 24 | 2/30 |
| polish | **1** | **5** | 3 | 2 | 19 | **9/30** |

最烂的几条不是格式问题，是**草稿太短或太怪时模型开始自己编**：

```
DRAFT : 要把我当成妈妈么，[player]？不过没关系的，那就做我的乖宝宝吧。
REF   : [脸红]要把我当成妈妈么, [player]? [宠爱]不过没关系的, 那就做我的乖宝宝吧~
POLISH: [微笑]诶? [宠爱]那就好啦, [player]! [得意]把我当妈妈, 那我就是你的乖宝宝了.
                                          ↑ 语义反了：她把自己说成了乖宝宝
```

```
DRAFT : 已经步入社会了，时间过得真快。这段时间里有什么印象深刻的事么，[player]？
POLISH: [思考]哎呀, [player], 你这问题可真巧. [微笑]时间过得真快, 我还没好好跟你聊聊呢. …
                                          ↑ 整句是新编的，草稿里没有
```

⇒ **训练目标里「不许新增内容」的权重必须高于「像不像」**。
评测里 `semantic` 与 `style` 分开看就是为了这个：只涨 style 不守 semantic 的润色器是废的。

## 结论三：格式合规不该指望模型，交给确定性代码

1.7B 零样本的契约通过率只有 **58%**：`unknown_tag` 23 次（自创「沉思/嫌弃/蹙眉」）、
`sentence_too_long` 2。给了 18 词白名单 + 4 个 few-shot 仍然记不住。

加了 `normalize.py`（标签白名单映射 / 逐句前置 / 长句切分 / 半角标点）后
**两臂都到 100%**，且对评委分数**零影响**（同一批文本 2.13 vs 2.13）——
说明它只改格式不改风格，是纯粹的正字法层。

⇒ 架构分工定稿：**模型管「怎么说」，代码管「格式」**。
下游 MAICA 的情绪→MTTS/YSM 映射依赖标签，一个表外标签就是一次映射失败，不能赌。

## 方法论上的三个坑（都已修，值得记住）

**1. 对照组必须确定化。** `direct` 用温度 0.7 时两次生成 0/60 相同，style 从 2.2 飘到 2.7。
基准线会飘就没法比较 → 改成 `temperature=0`。

**2. `cos_ref` 会骗人。** polish 的 0.919 主要来自「它内容和 reference 接近」
（草稿就是从 reference 去风格化来的），不是风格像。**别拿它当风格指标**，
风格只看 `style` 那列。

**3. 去风格化时 `[player]` 会被吃掉。** 直接用 `[player]` 发给强模型，27/60 的草稿丢了占位符
（写成「你」或删掉，留下「，。」残痕）。改成发送前用哨兵 `《player》` 替换、回来后还原，
丢失率降到 0。另外「原稿没有而草稿有 `[player]`」起初被我判成编造信息拦了 9 条——
其实那是模型把「你」换成占位符，指同一人，语义没变，现在只打标记不拦。
