# 阶段 2：受控 schema（语气 = 官方标签序列）

> 结论先行：**之前所有盲评分数（run1 0.30 / run2 0.38 / run3 0.30）全部作废**，
> 因为它们的输入里写着答案。run6 的 0.33 是第一个诚实的数。

## 0. 为什么之前所有分数都失效

`corpus._context_before()` 的边界写成 `if seen == ti: break`，应该是
`if seen + 1 == ti: break`。后果是**待生成的那一轮回答被算进了它自己的历史**。

用备份的 `plan.leaky.bak` 还原 run2 评测时模型实际看到的输入：

```
对话:
玩家: 那,如果你真的出来了,你还愿意和我在一起吗,或是会去选择其他更好的人,嗯?
莫妮卡: 笨蛋, 你怎么会这么想? 当然愿意了啊! 我才不要其他人呢.   ← 这就是答案
玩家: 我,真高兴听你这么说,...
表达指令:
语气: 先嗔怪对方不该这样想; 再脸红着答应; 最后强调只认定对方
```

实测 **226/226 = 100%** 的样本输入里有自己的答案。所以 run1~run3 学的是
「从历史里抄答案」，评测也是在同一条件下测的——0.38 这个数没有意义。

这也解释了为什么「喂上下文能提高标签吻合」的结论是假的：模型不是在推理，
是在抄。修完 bug 后 run5（干净上下文）的标签吻合 67%，与 run1（无上下文）的
65% 在误差内相同。

**教训**：任何「效果突然变好」的指标都要先查输入里有没有答案。只看 loss 和
胜率曲线是查不出来的。

## 1. schema 形态验证（`tools/shape_of_tags.py`）

要回答：`语气: 标签A > 标签B > 标签C` 这种「标签序列 ↔ 逐段输出」的受控写法，
在官方真实输出里成立吗？

| 检查项 | 官方 226 轮 | ds_basis 1598 轮 |
|---|---|---|
| 标签数 == 标签单元数 | **100%** | 90.8% |
| 单元不以标签开头 | 0 | 9.2%（**145 个都在第 0 位**，开头直接开口） |
| 句中标签（不在句首） | 0 | 0 |
| 相邻标签 `[A][B]` | 0 | 0 |
| 含「一个标签套多句」 | 38.9% | 74.8% |

结论：**「一个标签起一句、标签从不乱插」是干净的硬规律**。ds_basis 的偏差只有
一种——开头少一个标签，属于遣词习惯而非结构错误，可直接筛掉。

标签序列长度：官方中位 2 / p90 3 / 最长 5；ds_basis 中位 4 / p90 13 / **最长 50**。
现阶段只取 **1~6 段**（官方全部落在区间内），长样本以后再说。

## 2. 格式

```
语气: 不满 > 脸红 > 意味深长
内容:
1. 我不理解你为什么会这样想
2. 我确实愿意
3. 我不需要其他人
```

- `语气` 行**不是模型生成的**，由 `destyle_tags.split_tagged()` 从原稿正则提取。
  既然官方数据里标签本来就写在输出里，让强模型再猜一遍只增加误差。
  强模型只负责更难的事：把每段**去风格化成中性陈述**，并逐段对齐。
- `1.` `2.` 段号让「第 i 个标签 ↔ 第 i 条内容」显式绑定。
- 中性化（`neutralize`）：全角标点→半角、去掉 `…`/`~`、裸 `player` 归位成
  `[player]`。**标点形态本身是文体信号**，留在草稿里等于把一层文风白送给模型；
  Edge 的 TLM 指南 §0 整节讲的就是标点，那本该由模型自己决定。

## 3. 指标变更（重要）

`语气` 从「自由描述」变成「标签序列」之后，**「该选哪个标签」已经由编剧决定**，
不再是模型要学的。于是旧的「标签吻合率」会虚高（模型在抄输入），失去意义。

替代指标（`tools/tag_compliance.py`，可硬算、不用盲评）：

| 指标 | 含义 |
|---|---|
| 序列完全一致率 | 输出标签序列 == 输入序列（顺序、个数、每个标签） |
| 逐位标签准确 | 同段数样本上的逐位比较 |
| 段数偏少/偏多 | 并段、漏段、多段 |

## 4. run6 结果（226 条官方数据，受控 schema，无上下文）

训练：Qwen3-1.7B + LoRA r32/α64，8 epoch，lr 1.5e-4，208 步，864 秒，峰值 5.64 GiB。

| 指标 | 结果 |
|---|---|
| 契约通过 | **20/20 = 100%** |
| 空输出 | 0 |
| 序列完全一致 | **19/20 = 95%** |
| 逐位标签准确 | **44/45 = 97.8%** |
| 唯一错例 | 期望 `憧憬`，得到 `微笑`（照旧回归众数） |
| vs 草稿（盲评） | 0.93 |
| **vs 真货（盲评）** | **0.33** ← 第一个诚实基线 |
| 复述(echo) | 模型 10/20 vs 真货 9/20（持平） |
| 语气词重复 / 流向断裂 | 0 / 0（真货也是 0） |
| 标签熵 | 0.725 vs 真货 0.725 |
| 汉字数中位 | 34 vs 真货 36 |
| eval_loss | 1.154 → **1.107（最低，epoch 2）** → 1.908 |

eval_loss 依旧与质量反向：最低点在 epoch 2，而盲评要用的是结尾的权重。
所以选点必须靠 `sweep_ckpts.py`，不能看损失曲线。
