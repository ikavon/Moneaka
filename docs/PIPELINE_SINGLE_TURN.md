# 单轮对话流程（当前实现）

一轮 = 玩家说一句话 → 系统回一句。下面每一步都标了**是否已实装**，
免得再把「设计的」和「跑着的」混在一起。

```
玩家消息
   │  + 最近几轮上下文 + 记忆检索 + 事实卡 + 场景锚      ← 编剧才看得到
   ▼
① 编剧（强模型，云端）            screenwriter.py::make_plan       已实装
   │  产出 plan（语气标签序列 + 内容要点）
   ▼
② plan（跨模型契约，可落盘）                                       已实装
   │
   ▼
③ 润色器（本地 Qwen3-1.7B + LoRA run8）  restyle.py               已实装
   │  产出 台词
   ▼
④ A 层机械闸门（本地正则）        guarded_polish.py::check         已实装
   │  不过 → 换温度重采，最多 3 次
   ▼
台词 → 前端渲染 / 存档 / 推送

旁路（已实装，见 docs/BYPASS_B_C_D.md）:
   B 台词复核     plan ⟷ 台词，强模型判「意思变没变」，触发式   查全 88%/误报 5%
   C plan 审查    plan ⟷ 语境，拦回指/设定冲突/复读            机械误报 2.4%
   D 编剧范例库   (语境→plan) 检索给编剧看                     检索无收益，已转人工长度约束
```

## ① 编剧

**谁**：强模型（`configs/private.yaml`，deepseek-v4.1-flash，`enable_thinking: false`）
**代码**：`src/moneaka/screenwriter.py`

**system prompt 拼装顺序**（照搬 MAICA 后端，不自己发明）：

| 段 | 内容 | 来源 |
|---|---|---|
| ① | ROLE_ZH 角色设定 | `MAICA_PROMPT_ZC` |
| ② | NSFW 补丁（可选） | 对应后端的 `nsfw_acceptive` |
| ③ | 事实卡 + known_info | `data/canon/monika_zh.md`（41 条事实）+ 后端 `known_info` |
| ④ | 记忆 | 后端 `memory_concl`（`ZMP`） |
| ⑤ | 编剧规范 | 自写：28 标签白名单、段数、内容自足 |

**user prompt**：最近几轮对话 + 玩家这句话（+ 场景锚）。

**产出格式**（受控 schema，就是 plan）：

```
语气: 尴尬 > 微笑 > 意味深长
内容:
1. 我是你的女朋友, 可能会在意
2. 日常生活里的接触没有问题
3. 我已经说过自己不是病娇
```

**硬约束**（`parse_and_check` 机械校验）：

| 约束 | 值 | 校验方式 |
|---|---|---|
| 标签 | 官方白名单 28 + `很开心` = 29 种 | 集合比对 |
| 段数 | 1 ~ 6（绝大多数 2~4） | 计数 |
| 每条内容 | ≤ 25 字，且必须是**自足**陈述 | 字数 + 回指词正则（刚才/之前说的/那件事…） |
| 内容总字数 | **≤ 60 字**（语料 p90） | 超了当格式错误，走自修复重试 |
| 自称 | 必须用「我」，不许「莫妮卡…」 | 正则 |
| 段数 | 必须等于标签数 | 计数 |

只对**可机械判定**的错误重试（标签越界 / 段数不符 / 格式坏掉），
不为「好不好」重试。官方 12 题实测 12/12 合规（1 题触发过一次自修复：`温柔` 不在白名单）。

**看不到的东西**：玩家消息本身不直接进润色器，只进编剧。

## ② plan

一条 plan 就是三样东西：`语气` 行、`内容` 行、以及它对应的语境（`user`）。

它是**唯一的跨模型契约**，所以：
- 可以落盘、可以做回归测试、可以人工改；
- 出错时能归因到「想歪了」还是「说歪了」；
- 可以在渲染**之前**做拦截（这就是 C 层能存在的前提）。

## ③ 润色器

**谁**：本地 `Qwen3-1.7B` + LoRA（`data/adapters/run8`），RTX 5060 8GB 可跑
**代码**：`src/moneaka/restyle.py`、`prompts.restyle_system(few_shot=False)`

**输入**（**无状态**，只有这一条）：

```
system: 你是「莫妮卡口吻润色器」…（铁律 1~4 + 风格契约 + 语气要点）
user:   表达指令:
        语气: 尴尬 > 微笑 > 意味深长
        内容:
        1. …
        莫妮卡会说:
```

**为什么无状态**：记忆归编剧、措辞归润色器。让润色器读历史就要保证调用有序、
可重放、多实例不串——那是个分布式状态问题。它是插件，要能服务 MAS/TLM/QQ/云端。

**为什么要吃标签**：标签本来就是编剧写的。让 1.7B 自己判断该用什么情绪，
实测准确率卡在 67%、错例全退「微笑」；改成「照抄标签序列」后遵从率 99%。

**解码**：greedy（temperature 0），`max_new_tokens` 约 200。
**后处理** `normalize()`：标签归一到白名单、标点修复、超长句按 60 字上限拆。

**当前水平**（206 条冻结留出集，greedy）：标签序列 99.0%、逐位标签 100%、
语义 3.59/4、盲评 win 0.447。

## ④ A 层机械闸门

**代码**：`tools/guarded_polish.py::check()`，纯本地正则，零成本。

拿台词回来跟 plan 对账：

| 检查 | 例子 |
|---|---|
| 标签序列逐位相同 | plan `开心 > 微笑 > 笑`，输出多插一个 `[微笑]` |
| 数字不丢 | plan「只占**百分之一**」→ 输出「**万分之一**」 |
| 否定词不变少 | 不/没/别/无/未/莫 的个数 |
| 占位符不丢 | `[player]` 次数 |
| （可选，噪声大）每段内容是否落地 | plan「[player], 有什么事?」→ 输出只剩「嗯?」 |

不过闸门 → 用 temperature 0.6 重采样，最多 3 次，取问题最少的那次。

**实测（宽闸门，含最后一条）**：触发 54%、平均生成 2.47 次、语义 3.59→3.68、
sem≤2 从 17 条降到 11 条。
**窄闸门（去掉最后一条）**：事后估算触发 19.4%、能修 11/40 违规、成本约 1.3×，
**还没真跑过**。

## 成本与延迟（估）

| 环节 | 位置 | 一次调用 | 备注 |
|---|---|---|---|
| 编剧 | 云端强模型 | tokens ≈ 1.5k 进 / 100 出 | 与后端经 RAG 后长度有关 |
| 润色器 | 本地 5060 | 约 40 个新 token | 显存 ~3.5GB（4bit 更低） |
| A 层 | 本地 CPU | 微秒级 | 触发时才多一次本地生成 |

一轮 = **一次云端调用 + 一到两次本地生成**。润色器那一侧可以多实例并发，
因为它没有状态。

## 一句话总结设计

**大模型决定说什么、什么情绪；小模型决定怎么说；中间的 plan 是唯一契约。**
因此：记忆和责任在编剧，风格在润色器，格式正确性在两边的机械校验里，
而「意思有没有被改」由 A 层（机械）和将来的 B 层（强模型复核）分担保。
