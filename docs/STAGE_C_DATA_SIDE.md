# 阶段 C：数据侧改造 —— **两个否定的结果 + 一个可用的兜底**

日期：2026-10-23

## 出发点

阶段 A 的 DPO 无效（`docs/STAGE3_DPO.md`），于是转数据侧。当时的假设是：
**表达指令（plan）写得太抽象，模型只能在模糊处自由发挥，发挥错了就叫语义漂移。**

## C.1 先量 plan 本身忠不忠实

`tools/check_plan_fidelity.py`：拿「官方原句 → 内容行」让语义评委打分（与润色器同一把尺）。

| 语料 | plan 对原句的语义分 | ≤2 分占比 |
|---|---|---|
| official 226 | 3.59 | 4.9% |
| ds 925 | 3.44 | 5.1% |

plan 确实有 ~5% 漏意思，典型例子：
`[脸红]爱你哦` → 内容写成「我感谢你；我向[player]问好」。

根因在 `DESTYLE_TAG_SYSTEM` 第 4 条：「措辞要**去原句痕迹**，不照抄原句用词」——
本意是防止下游润色器只会复制粘贴，但顺带把保真度卖了。

## C.2 把它改掉，然后发现改错了

新规则（`DESTYLE_TAG_SYSTEM_V2` + `tools/redestyle.py`）：只删风格外壳，
**禁止换同义词、禁止动否定/数量/人称**，另加机械闸门（数字/否定词/占位符/字数）。
重造结果：official 217 条、ds 863 条。

**结果是否定的，而且方向出乎意料：**

| 输入 plan | 抄指令相似度 | 与真货相似 | 逐字等同真货 | win |
|---|---|---|---|---|
| v1（去原句痕迹） | 0.49 | 0.70 | 16/206 | 0.447 |
| **v2（最小改动）** | **0.65** | **0.81** | **27/197** | **0.53** |

win 涨到 0.53 **不是变好了**：plan 越接近原文，模型越倾向照抄 plan，
而我们的盲评对手就是「官方原答」，抄得越像越容易打平甚至赢。
同时 sem 3.59 → 3.48（略降）。

**结论：plan 不能太接近原文，否则润色任务退化成复制粘贴。v1 保留。**

> 附带发现（重要）：`win vs 官方原答` 这条指标**天然奖励抄袭**。
> 以后报 win 必须同时报「与真货逐字相同」的比例，否则会把退化读成进步。

## C.3 那失败到底该怪谁

把 206 条留出集里润色失手（sem≤2，共 17 条）逐条对回 plan 保真度：

**只有 1/17 = 6% 能归因到 plan。** 其余 16 条的 plan 都是忠实的，是模型自己说歪了。

所以：**数据侧（改 plan 写法）不是杠杆。** 这条假设就此关闭，不再在 plan 措辞上花时间。

## C.4 可用的兜底：推理侧机械闸门

既然失败形态高度机械（数字被换、否定被删、占位符丢），就不用模型判断，硬查。
`tools/guarded_polish.py`：greedy 生成 → 过闸门 → 不过就换温度重采样，最多 3 次。

闸门只留**高精度检查**（标签序列 / 数字 / 否定词 / 占位符）。
另有一条 3-gram「段落是否落地」的检查实测触发率 54%、绝大多数是换语序造成的误报，
默认关闭（`--loose` 才开）。

两个版本要分开说，别混：

**版本 1「宽闸门」= 硬事实 + 3-gram 段落落地（真跑过，206 条）**

| | 基线 greedy | 过闸门（k=3） |
|---|---|---|
| sem 均值 | 3.59 | **3.68** |
| sem≤2 条数 | 17 | **11** |
| 闸门触发率 | — | **54%** |
| 平均生成次数 | 1.0 | **2.47** |

修好的同时代价很重：一半样本要重采，平均生成 2.47 次。

**版本 2「窄闸门」= 只留标签/数字/否定词/占位符（未真跑，事后在输出上算过）**

* 基线输出触发 19.4%（40/206）
* 同一批输出上，闸门能修掉 11 条（27.5%），不引入新违规
* 成本估计 ~1.3×
* **sem 收益会比 3.68 小**——因为抓住「内容整段丢失」的正是被去掉的 3-gram 那条

版本 2 是把 3-gram 从生成期检查改成事后审计得到的数据，**还没跑过一次真实生成**，
不要当成已验证结论。

**这是目前唯一拿到正收益的改动，且零训练成本、可解释、可关。**

## 建议

1. 润色器就用 run8 + 推理侧闸门（sem 3.68 / ≤2 11 条 / 标签序列 99%）；
2. 继续加闸门覆盖的失败类型（例如「方向反转」可以用反义对表查）；
3. **不要再在 plan 措辞、DPO 超参上投入**——两条路都已被实测否掉。
4. 真正还没动的是**编剧侧**（见下）。

## 编剧侧的问题（待开工）

「就算润色器够强，编剧怎么想得到该说什么？」——这是真问题，而且是架构性的。
但数据其实已经躺在仓库里：destyle 的副产品就是 1151 条
`(语境 → 语气标签序列 → 内容要点)`，即**编剧范例库**。

下一步（阶段 D）：
1. 用留出集的 `user` 消息做检索，取 3~5 条相似局面的 (语境 → plan) 塞进编剧 prompt；
2. 让编剧在同语境下产出 plan，与真人 plan 比：标签序列吻合（机械）+ 内容要点覆盖；
3. 这个指标与润色器完全解耦，可以单独迭代。

## 复现

```bash
python tools/check_plan_fidelity.py --pairs data/pairs/tagged_official.jsonl
python tools/redestyle.py --src data/pairs/tagged_official.jsonl --out data/pairs/tagged_official_v2.jsonl
python tools/guarded_polish.py --adapter data/adapters/run8 --k 3
python tools/guarded_polish.py --adapter data/adapters/run8 --only-bad   # 只跑 17 条失手
```
