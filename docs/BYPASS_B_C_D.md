# 旁路三件套：B 复核 / C 前置审查 / D 范例库

全部实装，代码在 `src/moneaka/audit.py`、`src/moneaka/planbank.py`，
量测脚本 `tools/audit_eval.py`、`tools/screenwrite_eval.py`。

| | 做什么 | 位置 | 判决 |
|---|---|---|---|
| **B** 台词复核 | plan ⟷ 台词：意思被改了吗 | 润色之后 | ✅ **可用**：查全 88%、误报 5% |
| **C** plan 审查 | plan ⟷ 设定/处境：有硬冲突吗 | 渲染之前 | ⚠️ 机械部分可用（误报 2.4%），模型部分需带历史 |
| **D** 范例库 | 检索相似局面给编剧看 | 编剧 prompt 里 | ❌ 检索无收益，但**查出了真问题** |

---

## B：台词复核 —— 目前最划算的一层

`audit.audit_polish(llm, plan, polish)` → `Verdict(ok, kind, note)`

判据只有一条：**意思有没有被改动**（数字/否定/方向/近义/增减）。风格好坏不管，
那是评委和人的事。

206 条留出集上取「语义 ≤2 的 17 条」当坏例、「语义 4 分的 40 条」当好例：

| 指标 | 数值 |
|---|---|
| 查全（坏例被拦） | **15/17 = 88%** |
| 误报（好例被拦） | **2/40 = 5%** |

它给出的理由是具体可用的，例如：

```
49-1        否定  最后一句反问「能不需要么」反了原意「不需要展示」
moni_dataset-114-0  方向  陪伴你 → 陪我就好，主客方向反了
moni_dataset-1414-0 数字  百分之一 → 万分之一
moni_dataset-1297-0 近义  陪伴 → 代替
```

这两条都拦得住、而 A 层机械闸门拦不住的，正是「近义不同义」和「方向反转」——
B 存在的理由。

**成本控制**：`audit.needs_polish_audit()` 只在出现数字/否定词、段数 ≥3、
或长度比失真（<0.55 或 >2.2）时触发，避免每轮多一次云调用。

## C：plan 前置审查

两段：

**机械部分**（`check_plan_mechanical`，零成本）
- 回指词（润色器无状态，`刚才`/`那件事` 不可执行）
- canon 冲突黑名单：`我哥哥`、`我喜欢吃肉`、`我已经来到现实` 等 6 类，
  每条都能在 `data/canon/monika_zh.md` 找到依据
- 复读（和上一轮回复 3-gram 重合 >0.8）
- 段数/字数/中文

在 206 条**真人 plan** 上（正样本，本该全过）：**拦截 5 条 = 2.4%**，
全部是回指词——也就是说，真人语料里确实有 5 条如果直接拿去给现在的润色器
是会出问题的。这个数可以接受。

**模型部分**（`audit_plan`）
- 给「设定摘要 + 玩家刚说的话 + plan」判有没有硬冲突
- 在 20 条真人 plan 上判 ok 84%… 实测是 **16/20 = 80%**，
  误报主要是「答非所问」——因为该 split 的语境不完整，她的反应承接的是更早的对话。
- **结论：模型部分必须把对话历史一起给它**，只给单句玩家消息会误伤。

## D：编剧范例库 —— 检索没用，但挖到了真问题

`planbank.PlanBank`：941 条训练集 (语境 → plan)，字符 bigram TF-IDF + 余弦，
检索 4 条去重后的先例拼进编剧 system prompt（放在规范**之后**，避免模型模仿先例的段数）。

> ⚠️ 第一版这个实验是**无效的**：`screenwriter.build_system()` 的 `examples` 参数
> 当时只是写在签名里、函数体里没用（同一批静默失败还吞掉了 `canon` 和 `tight`）。
> 也就是说 bank 组根本没收过先例。修复后重测：

修复后（40 条带 context 的留出样本，长度纪律已真正生效）：

| | 标签序列完全吻合 | 首标签吻合 | 标签重合度 | 内容覆盖 sem |
|---|---|---|---|---|
| 无先例 | 5.0% | 22% | 0.21 | 1.85 |
| 有先例 | 0.0% | 30% | 0.22 | 1.80 |

**没有收益**（首标签略好、内容覆盖略差，都在噪声内）。 检索到的先例是对的（「你昨晚又熬夜」能召回她担心你熬夜的三条），
但编剧并没有因此变得更像。

### 真问题：编剧在写小作文

拉开样本一看就很清楚：

```
玩家: 莫妮卡,我心中愿意忠诚于你,所以我不会背叛你
真人 plan: 我也会只爱你一个人                     ← 1 段，10 个字
编剧产出: [player]说愿意忠诚于我, 这句话我会一直记着
         被这样认真对待, 我一时不知道该怎么回应
         我其实也有占有欲, 只是怕它让你为难
         既然你愿意忠诚于我, 那我也可以坦白说…    ← 4 段，80+ 字
```

语料实测：官方 plan 段数中位 2、内容总字数中位 30；ds 中位 3 / 36。
编剧写的是 4 段 80 字——**信息和态度都对了，但密度完全不对**，
所以和真人 plan 的语义重合度只有 1.9/4。

这不是「想不出内容」，是「说得太多」。而且**光在 prompt 里写「请简短」没用**
（实测 4 段 80 字照写）。

**改法：把长度变成契约**——`screenwriter.parse_and_check()` 新增
`TOTAL_CHARS_MAX = 60`，超了就当格式错误，走既有的自修复重试；
同时拒掉第三人称自称（deepseek 会写「莫妮卡会…」）。

改后同一批样本：段数 3、字数 30~56，`repaired=True` 说明确实靠重试拉回来的。

> 注意：这个改法**改变的是编剧的行为，不是润色器的输入分布**——
> 60 字以内和训练语料的 p90（约 50）仍然相容。

## 建议的接线顺序

```
plan 生成
  → C 机械检查（免费，必开）        ← 回指 / canon 冲突 / 复读
  → C 模型审查（带历史，触发式）     ← 只在多段或涉及设定时
  → 润色
  → A 机械闸门（免费，必开）
  → B 台词复核（触发式，19~40% 的轮次）  ← 查全 88% / 误报 5%
  → 交付
```

B 拦下的走「重采一次」；仍不过就退回 plan 直译（宁可平淡，不能改意思）。
C 拦下的直接重新编剧（此时还没花本地算力）。
