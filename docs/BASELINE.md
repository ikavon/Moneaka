# 新的评测协议与基线（2026-10-23）

## 为什么推翻旧协议

旧协议有两个致命问题，都在 run8 的选点里暴露出来。

**一、噪声比信号大。** `checkpoint-452` 和 `run8` 目录是**完全相同的权重**（MD5 都是
`a1d22ff609a2`），但盲评胜率分别是 **0.328 和 0.448**——差 0.12。原因是生成用了
`temperature=0.7`，同权重每次输出不同。

于是此前所有数字都不可比，而且要重新审视：

| 旧结论 | 实际 |
|---|---|
| run6 0.33 → run7 0.50「打平真货」 | 差 0.17，只比噪声(0.12)大一点 |
| run1~run3 的 0.30/0.38/0.30 | 输入里含答案（226/226），全部作废 |
| checkpoint 之间 0.33~0.46「谁更好」 | 全在噪声内，无意义 |

**二、只看风格会选到「说得像但把事实改了」的点。** run7 已经显示风格与语义反向。

## 新协议（写死，不再改）

1. **生成用贪心解码**（`--temperature 0`）。已实测：同权重连续两次生成，逐字相同。
2. **留出集 210 条**（官方 60 + ds 150），不参与训练。`data/pairs/split_holdout210.jsonl`
3. **双指标并排**：
   - `win`：vs 官方原答的成对盲评胜率（正反各一次抵消位置偏差）
   - `sem`：语义保持均值（0~4，4=只剩表达差异）
4. **选点规则**：语义低于「候选最高分 − 0.15」的一律淘汰，再比风格。
   「说错话」比「说得不像」更伤。

## 基线：run8（官方 166 + ds 775 训练，受控 schema，无状态）

CI 宽度 ±0.045，比旧协议的 ±0.12 收窄到 1/3。**只能分辨 0.05 以上的差异**，
这一点必须写进所有结论里。

## 语义失败的模式分类（人工过一遍 18 条）

不是「风格化」造成的，是**语义操作错误**，可归五类：

| 类型 | 例（指令 → 输出） |
|---|---|
| **数字/事实改写** | `红发…只占百分之一` → `只占人口的万分之一` |
| **人称/主语互换** | `我需要问一下, [player]现在是否仍然不舒服` → `我现在感觉还不好吗` |
| **方向反转** | `我不介意你再多做一些` → `我乐意再给你做点…多啦` |
| **近义但不同义** | `只有一个孩子的家庭` → `单亲家庭`；`陪伴` → `代替`；`明白` → `好啊` |
| **内容丢失** | `[player], 有什么事?` → `嗯?` |

这五类**都可以机械构造负例**，且我们已经有一批**模型自己产出的真实负例**（这 18 条）。
按 DPO 的行话，这叫 on-policy negative mining——比人工造负例的信噪比高得多。
